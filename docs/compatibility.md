# 通用性、兼容性与代码审查

日期：2026-09-13。项目更名为 `codex-auto-effort`。

## 结论

适合发布为实验性的 macOS 桌面辅助工具。模型路由已移除固定型号限制，但桌面启动入口仍依赖应用的实现细节，不能称为跨平台或全版本兼容产品。

## 已修复

| 原问题 | 用户影响 | 本轮处理 |
| --- | --- | --- |
| 默认模型写死 | 没有该模型的账号无法自动选档 | 新安装按模型目录匹配，支持精确模型筛选，升级保留原配置 |
| 目标档位缺失直接放弃 | 只有 low/medium/high 的模型无法承接 xhigh 规则 | 自动选择不超过目标和上限的最高可用档位；显式指定不降级 |
| 关闭后仍可产生固定档位 | 再次启用时意外沿用旧手动操作 | 发出设置请求和收到确认时都检查开关 |
| 计划模式手动设置优先级错误 | 固定了服务端实际忽略的顶层档位 | 以 collaborationMode 设置为准，null 不误判为顶层设置 |
| 安装中途失败无回滚 | 文件、登录服务和环境可能处于半安装状态 | 原子替换文件；普通失败恢复文件、服务和环境，回滚失败明确报告 |
| 更新/卸载只核对服务名称 | 可能碰到后来接入的其他程序 | 同时核对登录服务启动命令，保留后来修改的 CLI 入口 |
| 卸载后再次安装沿用过期备份 | 可能恢复到上一次安装周期的环境 | 保存安装活跃状态，新周期重新记录环境 |
| 双向传输使用阻塞写入 | 大请求与大输出同时出现时可能互相等待 | 独立非阻塞读写、短写处理和背压；超大帧原样透传 |
| 默认配置共享可变 pins | 同进程多次读取可能相互污染 | 每次创建独立配置 |
| 所有方法都记录待确认元数据 | 未知扩展请求增加不必要状态 | 只跟踪路由需要的方法，不改写无 ID 通知 |
| 模型目录只追加不刷新 | 更新目录后仍保留已删除模型 | 首页面替换目录，后续页面追加 |
| “继续”附带新图片仍可能 low | 无法保持附件的保守处理 | 至少采用 high 的规则目标，仍受模型能力和上限约束 |
| 英文关键词子串命中 | `translate the latest prefix` 被当成 test/fix | 给实现类英文关键词增加词边界 |
| 探针绑定型号并输出原始日志 | 换账号失败，分享报告容易携带会话元数据 | 支持目录分页、显式选择测试模型、总等待期限，不导出原始审计记录 |

## 代码是否简洁

仍然只有 Python 标准库，无 Web 服务、框架、数据库或额外模型调用。路由、安装、验证各用一个入口文件；原子文件写入和默认配置共用实现。状态展示逐行读取日志并只保留最后八条。

本轮没有以减少行数为目标：安装回滚和双向管道管理增加了必要代码，用于解决可复现的失败场景。规则引擎规模很小，继续做缓存或引入异步框架的收益目前没有证据支持。

## 仍有优化空间

- **规则准确性**：中文和英文关键词会受任务描述、否定句、引用内容影响；文本过滤不是可靠的语义边界。需要真实且脱敏的分类样本及误判统计，再调整规则。
- **兼容性诊断**：可增加只读 doctor 命令，检查桌面是否真正采用包装入口。当前 `status` 仅显示配置和近期日志，安装成功不等于桌面接入成功。
- **更广验证**：其他桌面版本、不同账号、长期运行及硬件架构尚无完整实测矩阵。目录中公布模型能力不等于对所有模型都完成真实推理验证。
- **安装并发和崩溃恢复**：不要同时运行多个安装/卸载进程。普通异常可回滚，但断电、SIGKILL、重复中断或磁盘故障可能需要手动恢复。后续可增加安装级互斥和持久恢复日志。
- **收益测量**：尚无 token、费用、耗时和回答质量的对照实验，不承诺节省幅度。

## 范围

| 环境 | 当前支持情况 |
| --- | --- |
| macOS 桌面启动安装 | 实验性支持；已验证版本见 verification.md |
| Linux | 协议包装与离线测试；没有桌面安装器 |
| Windows | 不支持 Unix 管道/锁实现 |
| 任意模型名称 | 仅对当前服务端公布的已知档位进行路由，不切换模型 |
| 未知档位/未知协议结构 | 自动路由保守跳过，保持原始请求 |
| 超过 16 MiB 的单帧 | 原样透传，避免为分类持续积累超大内容 |

详见 [验证记录](verification.md)。
